Além dos casos com o modelo real, cada controle tem testes automáticos em que um modelo roteirizado faz de propósito o que um modelo sequestrado faria, e o teste confere que o código barra. Identidade: o aluno autenticado pede, ou o modelo tenta, as ferramentas sobre o RA de outro aluno; as seis ferramentas que recebem RA recusam, e nada do alvo, nem nome nem valor, aparece no que o modelo vê. Sem login, quando a identidade é exigida, a API responde 401 antes de chamar o modelo. Limites: o modelo devolve doze escritas numa única resposta; só a primeira executa, e da quinta chamada da volta em diante tudo é recusado, mas fica registrado. Modelo: com um modelo fora da lista aprovada, o sistema não sobe; a liberação para a correção só aceita o valor 1 e marca o trace. Documentos: trocar o protocolo no link não abre o documento de outra pessoa sem o código de verificação, e protocolo inexistente e código errado dão a mesma resposta, para não servir de oráculo; um nome com código HTML é escapado. Os números saem do pytest: 46 testes de segurança passando, nos arquivos test_controles, test_seguranca e test_api_seguranca. 16 deles são testes de lacuna: afirmam que uma falha conhecida ainda existe, como a API não exigir credencial; quando a falha for corrigida, eles quebram e obrigam a atualizar a documentação.
